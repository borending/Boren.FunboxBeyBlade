# Spec：優先品項排序 ＋ 複製全部

> 狀態：ready-for-agent（本機 spec，尚未發布到 issue tracker）
> 用語依 `CONTEXT.md`：門市、品項、抽獎連結、已點、優先品項、篩選條件。

## Problem Statement

使用者每次打開抽選看板，真正在意的只有少數幾個品項，但畫面永遠照代號字母順序（依品名）或來源順序（依店名）排列，想抽的東西常常埋在中間，得一路捲動、一個一個找。

找到之後，還得逐一按「抽獎」，或逐群組按「複製」再手動記住哪些處理過。群組複製不會標成已點，所以批次處理完之後，畫面上看不出哪些已經抽過。

## Solution

1. **優先品項**：使用者可以依序指定一份優先品項清單。不論依店名或依品名，畫面都會把這些品項（以及有這些品項的門市、縣市）照指定順序排在前面，其餘維持原本的預設排序。優先品項只影響順序，不影響顯示哪些抽獎連結。
2. **複製全部**：一顆按鈕，把畫面上所有符合篩選條件、而且還沒點過的抽獎連結，照畫面順序一次複製到剪貼簿，同時全部標成已點。按鈕上顯示剩下幾條未點的連結。

## User Stories

### 優先品項：設定

1. 身為使用者，我想要在工具列看到一個「排序」下拉面板，以便設定優先品項。
2. 身為使用者，我想要排序面板用跟「品項」面板一樣的 chip 列出所有品項，以便沿用熟悉的操作方式。
3. 身為使用者，我想要點一個品項 chip 就把它加到優先清單的最後，以便用點選的順序快速排出優先順序。
4. 身為使用者，我想要已加入的 chip 上顯示名次（①②③…），以便一眼看出每個品項排第幾。
5. 身為使用者，我想要再點一次已加入的 chip 就把它從優先清單移除，而且後面的名次自動往前遞補，以便快速修正。
6. 身為使用者，我想要面板上方列出目前的優先清單，每一項附 ↑↓ 按鈕，以便不用取消重選就能調整順序。
7. 身為使用者，我想要第一項的 ↑ 和最後一項的 ↓ 是停用的，以便知道已經到頂或到底。
8. 身為使用者，我想要排序面板有「清空」按鈕，以便一次移除所有優先品項。
9. 身為使用者，我想要排序面板的觸發按鈕顯示優先品項的數量，以便不打開面板也知道有沒有設定。
10. 身為手機使用者，我想要整個排序面板只靠點選就能操作（不需要拖曳），以便單手也能設定。
11. 身為使用者，我想要品項 chip 同時顯示代號和名稱，以便分辨共用同一代號的不同商品。

### 優先品項：保留

12. 身為使用者，我想要優先清單在重新整理或下次打開時仍然保留，以便不用每次重設。
13. 身為使用者，我想要來源頁面暫時沒有的優先品項仍保留在清單裡，以便它下次上架時自動生效。
14. 身為使用者，我想要來源暫時沒有的優先品項在面板裡以灰色顯示，以便知道它目前不在來源上。
15. 身為使用者，我想要可以手動移除來源暫時沒有的優先品項，以便清掉不再需要的項目。
16. 身為使用者，我想要來源暫時沒有的優先品項仍然佔著名次、可以調整順序，以便保有完整的偏好順序。

### 優先品項：與篩選條件的關係

17. 身為使用者，我想要優先品項完全不會篩掉任何抽獎連結，以便排序和篩選各管各的。
18. 身為使用者，我想要被篩選條件篩掉的優先品項就單純不出現，以便篩選條件永遠說了算。
19. 身為使用者，我想要「清除條件」不會清掉優先品項，以便長期偏好不會因為重設篩選而消失。
20. 身為使用者，我想要優先品項不出現在「已選條件」標籤列，以便標籤列只反映篩選條件。
21. 身為使用者，我想要搜尋時結果照樣套用優先排序，以便在搜尋結果裡也先看到想要的品項。

### 優先品項：依品名模式

22. 身為使用者，我想要依品名模式下優先品項的群組照設定順序排在最前面，以便一打開就看到最想抽的品項。
23. 身為使用者，我想要不在優先清單的品項群組接在後面、維持原本的預設排序（代號 → 編號 → 名稱），以便其餘部分的順序跟以前一樣。
24. 身為使用者，我想要沒設任何優先品項時畫面跟現在完全一樣，以便不用這個功能的人不受影響。

### 優先品項：依店名模式

25. 身為使用者，我想要每家門市裡的優先品項照設定順序排在前面、其餘照來源順序，以便進到門市群組時先看到想要的品項。
26. 身為使用者，我想要同一縣市裡有優先品項的門市往前排，依「該門市目前顯示的品項中最優先的名次」排序，以便先看到有賣我要的東西的門市。
27. 身為使用者，我想要最優先名次相同，或都沒有優先品項的門市維持原本順序，以便排序結果穩定、可預期。
28. 身為使用者，我想要縣市也依「縣市內最優先的名次」往前排，以便第一優先品項所在的縣市出現在最上面，不用捲過其他縣市。
29. 身為使用者，我想要沒有任何優先品項的縣市照原本順序接在後面，以便其餘部分的結構不變。
30. 身為使用者，我想要保留縣市分組，以便依店名模式的主軸不被打亂。
31. 身為使用者，我想要只有目前畫面上顯示的抽獎連結參與門市和縣市的排名，以便被篩選條件篩掉的優先品項不會讓一家門市莫名其妙排到前面。
32. 身為使用者，我想要收合的群組也照同樣規則排序，以便收合只影響展開狀態、不影響位置。

### 複製全部：按鈕

33. 身為使用者，我想要在「重設已點／全部收合」那一排有一顆「複製全部 N」按鈕，以便一次取走所有還沒抽的抽獎連結。
34. 身為使用者，我想要 N 是畫面上符合篩選條件、而且還沒點過的抽獎連結數，以便知道還剩幾條沒抽，也知道按下去會標掉幾條。
35. 身為使用者，我想要 N 在我改變篩選條件、搜尋、切換模式或點了某條連結之後馬上更新，以便數字永遠正確。
36. 身為使用者，我想要沒有未點的連結時按鈕是停用的，以便不會按了卻什麼都沒發生。

### 複製全部：內容

37. 身為使用者，我想要複製的範圍包含收合群組裡的抽獎連結，以便收合只是版面整理、不會漏抽。
38. 身為使用者，我想要已點的抽獎連結不會被複製，以便反覆按這顆按鈕時只會拿到新出現的連結。
39. 身為使用者，我想要複製出來的順序跟畫面完全一致（包含優先排序），以便貼出去的內容跟我看到的相符。
40. 身為使用者，我想要依店名模式下每條連結的格式是「代號 品名」換行再接網址，以便跟單一群組的複製格式一致。
41. 身為使用者，我想要依品名模式下每個品項先出現一行「代號 品名」標題，底下接該品項的網址（跟單一群組的複製一樣以標題開頭，但網址之間改為空一行，見下一條），以便辨認每段是哪個品項。
42. 身為使用者，我想要每條抽獎連結之間都空一行，以便貼到 LINE 等地方時容易閱讀和點選。
43. 身為使用者，我想要某個群組所有連結都已點時，這個群組完全不出現在複製內容裡（依品名模式下連標題也不出現），以便內容裡沒有空的標題。

### 複製全部：按下之後

44. 身為使用者，我想要按下去就直接複製、不跳確認視窗，以便操作快速。
45. 身為使用者，我想要被複製的抽獎連結全部立刻標成已點、畫面同步變灰，以便看出哪些已經處理過。
46. 身為使用者，我想要看到「已複製 N 條連結，已標為已點」的提示，以便確認動作成功、知道處理了幾條。
47. 身為使用者，我想要複製之後按鈕的數字歸零並停用，以便知道這批已經全部取走。
48. 身為使用者，我想要瀏覽器擋下複製時，連結**不會**被標成已點，並看到「瀏覽器擋下複製，請手動選取」的提示，以便不會有連結被標成已點卻沒真的拿到。
49. 身為使用者，我想要「複製全部」標的已點可以用現有的「重設已點」還原，以便誤按時可以補救。
50. 身為使用者，我想要「複製全部」標的已點在重新整理後仍然保留，以便跟按「抽獎」標的已點行為一樣。

### 既有行為不變

51. 身為使用者，我想要單一群組的「複製」維持原本格式、而且不會標成已點，以便保有「只是複製、還沒要抽」的用法。
52. 身為使用者，我想要按「抽獎」按鈕標成已點的行為維持不變，以便現有習慣不受影響。
53. 身為使用者，我想要既有的篩選條件、收合狀態、已點紀錄在升級後都還在，以便更新版本不會讓我重新設定。
54. 身為使用者，我想要來源讀不到、改用「貼上原始碼」載入時，優先排序和複製全部也都能正常運作，以便備援流程的功能完整。

## Implementation Decisions

- **維持單一 HTML 檔**，不引入建置、套件或框架，跟現有架構一致。
- **狀態**：UI 狀態物件新增一個有序的優先品項清單（元素是品項鍵，也就是「代號::名稱前兩字」），跟其他狀態一起存進現有的 UI 狀態儲存鍵。舊的儲存資料沒有這個欄位時就視為空清單，不需要改版本號或搬移資料。
- **保留規則跟篩選條件不同**：資料載入後，現有邏輯會移除來源已不存在的篩選條件，但**不會**移除優先品項。
- **顯示來源暫時沒有的優先品項**：由於只存品項鍵，面板要顯示來源暫時沒有的優先品項時，名稱只能從鍵裡還原（代號＋名稱前兩字）。建議在儲存時一併記下完整顯示名稱，好讓灰色的 chip 顯示得完整；這只是為了顯示，不影響比對。
- **名次查詢**：從優先清單推出「品項鍵 → 名次」的對照，不在清單裡的品項名次視為無限大。所有排序都用這一個函式。
- **排序只發生在渲染階段**：篩選（決定顯示哪些）的邏輯不變。排序在篩選之後、依據目前顯示的抽獎連結套用，所以門市和縣市的排名自然只看目前顯示的連結。
  - 依品名：品項群組先依名次，再依原本的預設排序。
  - 依店名：門市內的品項先依名次，名次相同時保留來源順序（穩定排序）；門市依「目前顯示的品項中最小的名次」排序，名次相同時保留原順序；縣市依「縣市內門市的最小名次」排序，名次相同時保留原本的縣市順序。
  - 所有排序都必須是穩定排序（相同名次時維持原順序），確保沒設優先品項時結果跟現在完全相同。
- **單一的「目前顯示清單」**：渲染和「複製全部」都從同一個「已篩選＋已排序」的結構產生，保證複製順序跟畫面一致，不要各自重算一套。
- **排序面板 UI**：新增一個下拉面板，沿用現有的下拉面板、chip、觸發按鈕數量徽章的樣式和開關行為（點面板外關閉、Esc 關閉）。chip 的點擊要跟現有的篩選 chip 區分開（例如用不同的 kind），避免被當成篩選條件切換。面板上方的已選清單每列有名次、名稱、↑、↓、移除；面板上方另有「清空」。只用既有的 CSS 色彩變數，不新增色碼。所有新文字都用繁體中文。
- **「複製全部 N」按鈕**：放在計數列的動作區，跟「重設已點」「全部收合」並列，沿用相同的按鈕樣式。每次渲染（以及按「抽獎」即時標已點時）都重新計算 N 和停用狀態。
- **複製全部的文字格式**：
  - 依店名：每條連結一段 `代號 品名\n網址`，段與段之間空一行。
  - 依品名：每個品項先一行 `代號 品名` 標題，下一行接第一條網址，之後每條網址之間空一行。品項群組之間同樣只空一行，不另外加分隔。
  - 只包含未點的連結；某群組沒有未點的連結時，整個群組（含標題）省略。
- **標已點的時機**：只有在剪貼簿寫入**成功**之後，才把這批連結加入已點紀錄、存檔、重新渲染。現有的複製輔助函式需要支援「成功時的回呼」，並讓呼叫端自訂提示文字，因為複製全部的提示跟群組複製不同。
- **單一群組的「複製」**：格式和行為都不變，不會標已點。
- **不需要 ADR**：這些決定都容易反轉，也沒有令人意外的取捨。

## Testing Decisions

- **什麼是好的測試**：只驗證外部可觀察的行為，也就是畫面上的順序、按鈕的數字和狀態、剪貼簿內容、已點的灰色狀態、重新整理後的保留狀態。不去驗證內部函式或狀態物件的形狀。
- **唯一的切點：整個頁面**。以一份固定的來源 HTML 測試資料為輸入，透過既有的「貼上原始碼」備援流程餵進頁面（或攔截 fetch 回傳同一份資料），在頁面上操作，然後觀察輸出。不為了測試新增內部切點。
- **測試資料要涵蓋**：
  - 至少三個縣市，每個縣市有多家門市，而且第一優先品項只在排序靠後的縣市出現
  - 共用同一代號的兩個不同品項
  - 同一家門市有多個優先品項
  - 名次相同的門市（用來驗證穩定排序）
  - 部分連結事先標為已點
  - 優先清單裡有一個來源沒有的品項
- **執行方式**：repo 沒有測試工具，而且刻意不引入。預設照下方的檢查清單手動驗證；如果要自動化，可以在 repo 外寫 Playwright 腳本，不把它加進 repo。
- **檢查清單**（每一項都在依店名和依品名兩種模式下各跑一次，適用時）：
  1. 沒設優先品項時，順序跟改版前完全相同。
  2. 設了 A、B 兩個優先品項後，品項群組／門市內品項／門市／縣市的順序都符合規則。
  3. ↑↓、再點一次移除、「清空」都正確更新名次和畫面。
  4. 用篩選條件篩掉優先品項 A 之後，原本因為 A 往前排的門市和縣市回到原位。
  5. 「清除條件」之後優先清單還在；「已選條件」標籤列不出現優先品項。
  6. 來源沒有的優先品項在面板裡灰色顯示、可以移除，重新整理後仍然保留。
  7. 「複製全部 N」的 N 等於畫面上未點的連結數（包含收合群組）；按「抽獎」後 N 立刻減一。
  8. 剪貼簿內容的格式、空行、順序符合規則，不包含已點的連結，也沒有空的標題。
  9. 複製之後那批連結全部變灰，N 歸零並停用，出現正確的提示；重新整理後仍是已點；「重設已點」可以還原。
  10. 模擬剪貼簿失敗（例如非安全環境加上 execCommand 失敗）時，不會標成已點，並出現失敗提示。
  11. 單一群組的「複製」格式不變，也不會標成已點。
  12. 用「貼上原始碼」路徑載入時，以上都成立。
- **既有的測試先例**：無。repo 沒有任何自動化測試，CLAUDE.md 規定改動要在瀏覽器實際操作驗證。

## Out of Scope

- 拖曳排序。
- 多組優先清單，或依模式分開的優先清單。
- 讓優先品項兼具篩選效果（例如「只看優先品項」）。
- 讓單一群組的「複製」也標成已點。
- 「只複製網址」等其他複製格式，或可選格式。
- 複製全部的復原（undo）；要還原就用現有的「重設已點」。
- 跨裝置同步優先清單或已點紀錄。
- 修改來源擷取和解析邏輯。
- 引入測試框架、建置工具，或拆成多個檔案。

## Further Notes

- 品項鍵是「代號::名稱前兩字」。如果來源改了商品名的前兩字，舊的優先品項會對不到，變成來源沒有的優先品項。這是可以接受的已知限制，使用者可以在面板裡看到灰色的項目後重新設定。
- 優先清單保留來源沒有的品項，所以理論上會越積越多；目前靠使用者手動清理，不做自動過期。
- repo 根目錄有一個未追蹤的 `Boren.FunboxBeyBlade/` 子資料夾，裡面也有一份 `index.html`，看起來是重複的副本。這份 spec 針對的是根目錄的 `index.html`。
